# Лабораторная работа №3

**Задание**: Создание веб-сервиса со всей итоговой бизнес логикой (кроме авторизации), подключение его к БД и тестирование в `insomnia`/`postman`.

Создание **веб-сервиса** для получения/редактирования данных из вашей БД. Требуется разработать все методы для реализации итоговой бизнес логики вашего приложения. Для изображений команд RISC-V использовать `Minio`. В `README` проекта описать все HTTP методы и таблицы с их полями.

**Требования к веб-сервису**

Методы и `url` в `API` должны соответствовать `REST`. Для списка команд RISC-V (как в 1 лабораторной) нужно предусмотреть фильтрацию на бэкенде. Взаимодействие с БД через `ORM`. Записи в статусе `удален` на клиент не передаются.

Статусы нельзя менять с любого на любой: у `создателя` два разных метода, вернуть в `черновик` нельзя. В данной лабораторной пользователь `создатель` зафиксирован во всех методах — укажите его константой через функцию-`singleton`. Системные поля (ид, статусы, создатель и модератор, даты создания, формирования и завершения) передавать с клиента для изменения запрещено. Они вычисляются на бэкенде через авторизацию и бизнес-логику. В начале адреса каждого метода добавьте `/api`.

**Домен команд RISC-V:**

- GET список с фильтрацией (только опубликованные). Признак 0/1, если создатель команды совпадает с текущим пользователем.
- GET лента (только опубликованные).
- GET получения черновика (не более 1 записи для пользователя), ид не указывается.
- POST добавление + добавление файлов изображения и короткого видео (как файлы, а не просто URL), названия файлов сохраняются в полях БД, а сами файлы в `Minio`. Названия файлов генерируются на латинице.
- PUT публикации (смена статуса).
- DELETE удаление (только soft delete). Только команды этого пользователя.
- POST like (от текущего пользователя). Поле 0/1 (0 отменяет лайк, 1 ставит лайк).

**Домен пользователей:**

- POST регистрация.
- POST аутентификация (заглушка для 4-й лабораторной).
- POST деавторизация (заглушка для 4-й лабораторной).

## HTTP-методы

| Метод | URL | Описание |
| --- | --- | --- |
| `GET` | `/api/riscv_commands` | Список опубликованных команд с фильтрацией по `min_operands` и `max_operands` и признаком `is_creator` (0/1). |
| `GET` | `/api/riscv_commands/feed` | Лента опубликованных команд; необязательный `id`, переход к следующей команде через `id` и `next=true`. |
| `GET` | `/api/riscv_commands/draft` | Черновик текущего пользователя без передачи его ID. |
| `POST` | `/api/riscv_commands` | Создание черновика из `mnemonic` и файлов `image`, `video` в `multipart/form-data`; файлы сохраняются в MinIO. |
| `PUT` | `/api/riscv_commands/{id}/publish` | Публикация своего черновика с полями `description`, `operand_count`, `length_bits`. |
| `DELETE` | `/api/riscv_commands/{id}` | Логическое удаление своей команды. |
| `POST` | `/api/riscv_commands/{id}/like` | Установка (`like: 1`) или отмена (`like: 0`) лайка опубликованной команды. |
| `POST` | `/api/users` | Регистрация пользователя по `login` и `password`. |
| `POST` | `/api/users/authentication` | Заглушка аутентификации до лабораторной работы №4. |
| `POST` | `/api/users/logout` | Заглушка деавторизации до лабораторной работы №4. |

## Таблицы PostgreSQL

- `users`: `id` (`BIGINT`, первичный ключ), `login` (`VARCHAR(64)`, уникальный), `password_hash` (`VARCHAR(255)`), `role` (`VARCHAR(16)`, `user` или `moderator`).
- `riscv_commands`: `id` (`BIGINT`, первичный ключ), `mnemonic` (`VARCHAR(16)`), `description` (`VARCHAR(1000)`), `operand_count` (`SMALLINT`), `length_bits` (`SMALLINT`), `image_key` и `video_key` (`VARCHAR(255)`), `status` (`VARCHAR(16)`: `draft`, `published`, `deleted`), `created_at` и `published_at` (`TIMESTAMPTZ`), `creator_id` (`BIGINT`, внешний ключ на `users.id`). Для черновика `description`, `operand_count`, `length_bits`, ключи медиа и `published_at` могут быть пустыми; на одного пользователя допускается не более одного черновика.
- `riscv_command_likes`: `id` (`BIGINT`, первичный ключ), `user_id` (`BIGINT`, внешний ключ на `users.id`), `riscv_command_id` (`BIGINT`, внешний ключ на `riscv_commands.id`). Пара `user_id` и `riscv_command_id` уникальна.
