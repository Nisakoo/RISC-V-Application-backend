# Лабораторная работа №1

- **Цель работы**: выбор предметной области на весь курс, знакомство с разработкой бэкенда и создание дизайна трёх страниц.
- **Порядок показа**: показать задание по предметной области RISC-V; показать дизайн трёх страниц в Figma и соответствующие страницы приложения; показать сайт-референс и перечислить заимствованные элементы в CSS; показать три страницы приложения с серверной фильтрацией и объяснить три `GET`-запроса во вкладке Network; показать URL изображений и видео из MinIO в HTML-ответах, коллекции команд и трёх шаблонах; показать маршруты, три контроллера и реализацию серверной фильтрации.
- **Контрольные вопросы**: MVT, компоненты MVC в лабораторной работе, шаблонизация, HTTP и модель OSI, Web, HTML.
- **Задание**: создать дизайн приложения в Figma, реализовать базовую шаблонизацию каталога команд RISC-V и развернуть MinIO.

Необходимо разработать в Figma дизайн трёх страниц приложения, адаптировав основную стилистику сайта RISC-V International: три основных цвета с точными кодами, состояния наведения и форму карточек. В приложении должны использоваться реалистичные данные по теме RISC-V.

Базовый интерфейс состоит из трёх страниц в портретной мобильной компоновке. Внизу каждой страницы располагается панель навигации с пунктами «Лента», «Добавление» и «Плитка». В ленте автоматически воспроизводится короткое вертикальное видео, поверх которого размещены краткое описание с раскрытием, параметры команды RISC-V, количество лайков и кнопка «Следующий». На странице добавления те же данные представлены отдельными полями для изображения, видео, текста и параметров команды. В первой лабораторной поля можно заполнять, но сохранение и добавление команд не реализуются. На странице плитки все команды отображаются в два столбца; карточка содержит изображение, мнемонику, вычисленное по коллекции количество лайков и предметный параметр для серверной фильтрации. Нажатие на карточку открывает выбранную команду в ленте.

Для каждой команды задаётся один из трёх статусов: `draft`, `published` или `deleted`. В коллекции должна быть одна команда в статусе `draft`, которая отображается на странице добавления. Команды в статусе `deleted` в интерфейсе не отображаются. Поле фильтрации на странице плитки работает на сервере по числовому предметному параметру, а введённое значение сохраняется после запроса.

В приложении должно быть ровно три прикладных `GET`-запроса: лента по идентификатору команды, получение черновика и плитка опубликованных команд. Все данные страниц берутся из одной in-memory коллекции команд без БД. Поля команды должны быть атомарными и соответствовать первой нормальной форме. Редактирование и сохранение не реализуются, доступны только просмотр и серверная фильтрация. Кнопка «Следующий» сразу ссылается на идентификатор следующей команды. JavaScript не используется.

Для каждой команды загружаются собственные изображение и видео. Медиафайлы хранятся в MinIO под ключами на латинице, а модель содержит два отдельных поля для ключей изображения и видео. Изображения команд используются на всех трёх страницах. Единый стиль приложения сохраняется для последующих лабораторных работ, а CSS вынесен в отдельный файл.
