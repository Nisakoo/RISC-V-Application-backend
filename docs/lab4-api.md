# Веб-сервис лабораторной работы №4

Запуск из корня проекта: `make lab4-run`. Команда поднимает PostgreSQL, Adminer, Redis и MinIO, применяет миграции и запускает Go-сервер на `http://localhost:8080`. Swagger UI: `http://localhost:8080/swagger/index.html`.

## Переменные окружения

Переменные задаются в `backend/docker/.env` (образец — `backend/docker/.env.example`, файл `.env` в Git не хранится). К переменным ЛР3 добавлены:

| Переменная | Назначение |
| --- | --- |
| `REDIS_HOST`, `REDIS_PORT` | Адрес Redis, по умолчанию `localhost:6379` |
| `REDIS_PASSWORD` | Пароль Redis (`requirepass` контейнера) |
| `JWT_SECRET` | Секрет подписи JWT (HS256), не короче 32 символов; сгенерировать: `openssl rand -base64 48` |
| `JWT_TTL` | Срок действия JWT в формате Go, например `1h` или `30m`; по умолчанию `1h` |

Без этих переменных сервер не запускается и сообщает, какие значения отсутствуют.

## Swagger

Описание методов пишется аннотациями `swaggo` в коде обработчиков (`internal/handler`) и общей аннотацией в `cmd/api/main.go`. Спецификация генерируется в `docs/swagger` командой из корня проекта:

```bash
make swagger
```

Сгенерированные файлы `docs/swagger/docs.go`, `swagger.json` и `swagger.yaml` вручную не редактируются; после изменения аннотаций спецификацию нужно сгенерировать заново.

Для вызова методов создателя в Swagger UI нажмите **Authorize** и введите `Bearer <access_token>` из ответа `POST /api/users/authentication`. Без авторизации работают только список, лента, регистрация и аутентификация.

## Ответы и ошибки

Результат операции передаётся HTTP-кодом. Успешный ответ содержит сами данные; удаление и деавторизация возвращают `204 No Content` без тела. Ошибка возвращается объектом `{"message": "…"}`:

| Код | Ситуация |
| --- | --- |
| 400 | Некорректные параметры, тело запроса или системные поля в запросе |
| 401 | Нет JWT, неверный логин или пароль, неверная подпись, истёкший или отозванный токен |
| 403 | Роль пользователя не допускает действие |
| 404 | Команда отсутствует, удалена или принадлежит другому пользователю |
| 409 | Черновик уже существует или логин занят |
| 500 | Внутренняя ошибка; подробности пишутся только в журнал сервера |

## Проверка в Postman и Bruno

Импортируйте `docs/lab4-postman.json` в Postman. Для Bruno откройте **Import Collection** и выберите `docs/lab4-bruno-import.json` как коллекцию Postman v2.1. Коллекция содержит 10 запросов — по одному на каждый метод API.

1. Задайте переменные `login`, `password` (8–72 символа), `image_path` и `video_path`.
2. Выполните «01 Зарегистрировать пользователя» и «02 Аутентификация»: JWT из ответа записывается в переменную `access_token`.
3. Остальные запросы передают токен заголовком `Authorization: Bearer {{access_token}}` на вкладке Headers, вкладка Authorization не используется. Чтобы выполнить запрос от имени гостя, снимите галочку у этого заголовка: список и лента ответят 200, методы создателя — 401.
4. «07 Лента команд» вызывается с параметрами `id={{feed_command_id}}` и `next=true` и возвращает команду, следующую за `feed_command_id`; после ответа в переменную записывается `id` полученной команды. Чтобы получить ленту без id, отключите оба параметра.
5. После «10 Деавторизация» повторный запрос с тем же токеном возвращает 401.

## Просмотр Redis

```bash
docker exec -it riscv-redis redis-cli KEYS 'riscv.jwt_blacklist.*'
docker exec -it riscv-redis redis-cli GET riscv.jwt_blacklist.<jti>
docker exec -it riscv-redis redis-cli TTL riscv.jwt_blacklist.<jti>
```

Пароль Redis передаётся в контейнер переменной `REDISCLI_AUTH`, поэтому `redis-cli` внутри контейнера не требует флага `-a`. Значение ключа — логин владельца отозванного токена, TTL равен оставшемуся сроку действия JWT.

## Проверки

`make test` из корня проекта применяет миграции и выполняет все проверки. Тесты покрывают выпуск и разбор JWT (подпись, срок действия, алгоритм `none`), middleware (401, 403, гость на публичных методах), определение создателя по токену, деавторизацию через blacklist и работу с реальным Redis.
