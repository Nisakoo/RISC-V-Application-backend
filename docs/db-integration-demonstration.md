# Сценарий демонстрации ЛР2

## Подготовка

1. Выполнить `make lab2-run` из корня проекта.
2. Открыть приложение на `http://localhost:8080/riscv_commands/feed`.
3. Открыть Adminer на `http://localhost:8081` и подключиться к серверу `postgres` с параметрами из `backend/docker/.env`.

## Скриншоты 1–2: Adminer

1. Для опубликованной команды выполнить `UPDATE riscv_commands SET status = 'deleted' WHERE id = 4;`.
2. Выполнить `SELECT id, mnemonic, status FROM riscv_commands ORDER BY id;` и показать изменённый статус.

## Скриншоты 3–10: приложение

1. На странице плитки выбрать диапазон количества операндов и нажать «Показать».
2. Удалить опубликованную команду кнопкой «Удалить».
3. Открыть её прежний URL в ленте и показать ответ «Команда не найдена».
4. На странице добавления указать мнемонику, PNG/JPEG и MP4, затем нажать «Далее».
5. Показать новый статус `draft` через `SELECT` в Adminer.
6. Заполнить `assembly_example`, описание, формат, количество операндов и длину команды.
7. Нажать «Опубликовать» и показать переход в ленту.
8. Повторить `SELECT` и показать статус `published` и `published_at`.

## Скриншоты 11–13: изменение данных в БД

1. Изменить в Adminer `assembly_example`, `operand_count` или `length_bits` опубликованной команды допустимыми значениями.
2. Добавить или удалить строки в `riscv_command_likes`, сохраняя уникальность пары пользователя и команды.
3. Обновить ленту и плитку: значения параметров и счётчик лайков должны измениться.

## Скриншоты 14–21: код

Показать:

1. модель `RiscVCommand`;
2. SQL-миграции трёх таблиц;
3. три GET-контроллера;
4. POST создания черновика;
5. POST публикации;
6. GORM-запросы репозитория;
7. параметризованный `SQL UPDATE` в `SoftDelete`;
8. регистрацию ровно шести прикладных HTTP-методов.
